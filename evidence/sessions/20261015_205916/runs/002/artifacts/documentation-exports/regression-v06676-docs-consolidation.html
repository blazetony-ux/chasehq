Getting Started

Welcome to ChaseHQ-Native

What the project is, how the runtime and Workbench fit together, and where to begin.

Current release
v0.66.9.3 is the current promoted release; direct Windows qualification provenance is 0.66.9.3-RC5 SHA-256 19b7ed48edae98fd99f660ef56a949573050cabc2958fcdba2833a7888103961.

ChaseHQ-Native is both a native Chase H.Q. runtime and an evidence-driven reverse-engineering platform. The SDL window is the live game/render output; the Research Workbench is the browser-based control, inspection, scripting and documentation environment.

Core rule
Gameplay and rendering fidelity are the project. Tooling exists to make behaviour observable, reproducible and provable.
  • Use checkpoints or scenarios to start from known states.
  • Prefer API/scriptable experiments over one-off UI gestures.
  • Capture evidence with build, frame, checkpoint and source metadata.
  • Promote only sufficiently proven findings into authoritative knowledge.

Build and launch

Authoritative chqdev development build, runtime and release workflow.

chqdev is the de facto and authoritative build/release process. Use its bundled launcher for build/test/runtime/release work; PowerShell/BAT release tooling is compatibility/fallback only.

Development build/test

.\chqdev.bat build debug
.\chqdev.bat test debug

Launch/restart research session

.\chqdev.bat runtime restart
Strict test policy
There are zero tolerated CTest failures. Any CTest failure is fatal. Fresh Windows Mark-of-the-Web is repaired by chqdev; manual Unblock-File is not a normal step.

Your first reproducible investigation

A minimal checkpoint → action → capture → compare workflow.

  1. Load a canonical checkpoint.
  2. Apply one controlled intervention.
  3. Advance a bounded number of emulated frames.
  4. Capture structured evidence.
  5. Compare the changed state against the baseline.
  6. Record the conclusion only when the evidence supports it.

Example

api checkpoint.load file=stage1-driving-2352.chqstate run=false
api frame.snapshot name=baseline sprites=individual
api control.run-frames count=30
api frame.snapshot name=after sprites=individual
api image.compare a=baseline b=after hud=hidden

Release and prove-off workflow

One-command exact-archive qualification with deterministic packaging and regression proof.

From a fresh Windows extraction, the canonical release prove-off is chqdev qualify --fresh. Do not manually reproduce the release sequence unless diagnosing a failure.

Fresh qualification

.\chqdev.bat qualify --fresh
  1. Clean generated state and run doctor/preflight/trust normalization.
  2. Build Debug and require every CTest case to pass.
  3. Create a deterministic package, reproduce it byte-for-byte and verify the exact archive.
  4. Restart/check the exact runtime.
  5. Run the focused release regression.
  6. Run Full Regression.
  7. Record promotable=PASS only if every required stage succeeds.
Exact archive identity
Promotion evidence belongs to one immutable candidate ZIP SHA-256. Any source edit after packaging creates a new candidate identity.

See docs/RELEASE_GOVERNANCE.md and docs/RELEASE_PROCESS.md for the permanent rules.

Graphics Lab

Layered snapshots, HUD isolation and individual sprite controls.

Graphics Lab works with structured snapshots rather than ordinary screenshots. Exact reconstruction uses ordered contribution layers. Raw source layers are independent forensic views. The HUD can be shown normally, suppressed at source, or isolated by itself.

  • Normal / HUD hidden / HUD only frame views.
  • Exact contribution-layer reconstruction with native verification.
  • Raw logical source layers for road/background/sprite/text investigation.
  • Individual visible sprite hide/show, solo and opacity controls.
  • Per-sprite slot, map, palette, priority, zoom/flip and provenance metadata where available.
Exactness
Individual-sprite assets are forensic/exploratory. The aggregate sprite contribution remains authoritative for exact frame reconstruction.

Script Console

How to use the reusable script library and run history.

The Script Console is the preferred place to turn a successful manual experiment into a reproducible recipe. Scripts may call any documented Script API action through the generic api statement.

  • Use Validate before long runs when editing a script.
  • Use the Script Library for packaged diagnostics, surveys and regressions.
  • Run history records source, output, artifacts, build and session metadata.
  • Prefer include for reusable script fragments instead of copy/paste duplication.

Experimental / Game Lab

Reversible Chase H.Q.-specific turbo and speed experiments with API/script parity.

Game Lab groups confirmed gameplay manipulations into named reversible controls. Infinite turbo stock freezes 0x1003A2, infinite active turbo freezes the duration timer at 0x100414, and current speed set/freeze targets the confirmed 32-bit fixed-point field 0x10041C using user speed << 16; Run010 proved the older 16-bit helper could not intercept the 32-bit PC 0x8700 writer.

The purpose and shape of .chqscript.

.chqscript is intentionally small and deterministic. It is designed for repeatable research recipes and regressions, not as a general-purpose programming language.

Glossary

Quick definitions for common ChaseHQ-Native and research terms.

Checkpoint
Deterministic saved emulation state used to reproduce an experiment.
Contribution layer
Reconstruction PNG containing the pixels introduced or replaced at one compositor stage.
Documentation evidence attachment
Structured link from a knowledge entry to screenshots, layered captures, JSON/CSV traces, scripts, checkpoints or other proof, retaining build/source/caption metadata.
Evidence bundle
Portable ZIP containing script source, output, metadata and generated artifacts for a research run.
HUD isolation
Suppressing or isolating the identified text/HUD source at render time rather than masking fixed screen coordinates.
Native reconstruction maturity
Evidence ladder from UNKNOWN to NATIVE, with independent SHADOW/COMPARE required before claiming replacement parity.
Provenance
Trace from an observed effect back to the memory routine, object record or raw source data that produced it.
Raw source layer
Independent forensic rendering of one logical hardware source; it is not assumed to alpha-compose directly into the final frame.
Research API
Documented HTTP/debug action surface shared by Workbench tooling and repeatable research scripts.
Research Script
Small deterministic .chqscript language for repeatable experiments, regressions and evidence capture.
Scenario
Higher-level reproducible setup that drives the game into a known state before observation begins.
Semantic state
Gameplay meaning promoted only after the underlying address and producer/consumer path are sufficiently proven.
