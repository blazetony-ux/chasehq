Getting Started

Welcome to ChaseHQ-Native

What the project is, how the runtime and Workbench fit together, and where to begin.

Current proven release

v0.66.8.0 (2026-09-29): Forensic Timeline v1, portable automated timeline analysis/playback, and bounded Workbench history discovery are proven on Windows/SDL.

ChaseHQ-Native is both a native Chase H.Q. runtime and an evidence-driven reverse-engineering platform. The SDL window is the live game/render output; the Research Workbench is the browser-based control, inspection, scripting and documentation environment.

Core rule

Gameplay and rendering fidelity are the project. Tooling exists to make behaviour observable, reproducible and provable.

  • Use checkpoints or scenarios to start from known states.
  • Prefer API/scriptable experiments over one-off UI gestures.
  • Capture evidence with build, frame, checkpoint and source metadata.
  • Promote only sufficiently proven findings into authoritative knowledge.

Build and launch

Normal Windows development build and research launch workflow.

The normal Windows development entry point is Build-Debug.bat. It prepares the project, configures/builds the native target and runs the packaged tests. The research launcher then starts the SDL runtime, private debugger API and browser Workbench together.

.\Build-Debug.bat
.\Start-ChaseHQ.ps1
Known Windows test exception

A narrowly documented historical cpu_bus_rom_tests SEGFAULT may be tolerated only when it exactly matches the known signature recorded in validation documentation. Other failures remain blocking.

Your first reproducible investigation

A minimal checkpoint → action → capture → compare workflow.

  1. Load a canonical checkpoint.
  2. Apply one controlled intervention.
  3. Advance a bounded number of emulated frames.
  4. Capture structured evidence.
  5. Compare the changed state against the baseline.
  6. Record the conclusion only when the evidence supports it.

Release and prove-off workflow

Use cheap gates before Full Regression and keep one authoritative run/bundle lifecycle.

The canonical Windows build path is Build-Debug.bat. Do not bypass it with ad-hoc build or validator sequences.

  1. Build with Build-Debug.bat.
  2. Launch with Start-ChaseHQ.ps1 -Restart and require browser bootstrap READY.
  3. Check root/status/run-history/snapshot endpoints.
  4. Run Recovery / Fast Release Gate.
  5. Run the focused regression for the changed subsystem.
  6. Run Full Regression Suite once against the exact candidate intended for promotion.
One run, one bundle

A script run must create one run directory and generate bundle-manifest.json / bundle.zip only once at PASS, FAIL or CANCELLED finalization. Repeated Compress-Archive activity during individual commands is a runner defect.

See docs/RELEASE_PROCESS.md for the complete packaging, validation, discovery and lifecycle rules.

Layered snapshots, HUD isolation and individual sprite controls.

Graphics Lab works with structured snapshots rather than ordinary screenshots. Exact reconstruction uses ordered contribution layers. Raw source layers are independent forensic views. The HUD can be shown normally, suppressed at source, or isolated by itself.

  • Normal / HUD hidden / HUD only frame views.

  • Individual visible sprite hide/show, solo and opacity controls.
  • Per-sprite slot, map, palette, priority, zoom/flip and provenance metadata where available.

Script Console

How to use the reusable script library and run history.

The Script Console is the preferred place to turn a successful manual experiment into a reproducible recipe. Scripts may call any documented Script API action through the generic api statement.

  • Run history records source, output, artifacts, build and session metadata.
  • Prefer include for reusable script fragments instead of copy/paste duplication.

Trace a memory writer

Find which CPU/PC writes an address or range.

Start from a deterministic checkpoint, enable a bounded write trace, reproduce the state transition, then inspect writer PCs and transaction widths. For byte discovery, width=any avoids missing writes performed by a wider bus transaction.

api memory.trace.clear
api memory.trace.start cpu=A address=0x100303 length=1 width=any limit=256
api control.run-frames count=120
api memory.trace.stop
api memory.trace.tail count=50

Follow the proven turbo gameplay-to-TC0100SCN HUD path and inspect the active RAM characters directly.

The turbo gameplay/HUD chain is now substantially proven. Activation decrements 0x1003A2 and sets 0x10040F bit 1; the timer 0x100414 expires at 0x00D2. The HUD swaps the consumed slot from normal characters 0x7C..0x7F to active characters 0x0C..0x0F, then clears it at expiry.

Forensic Timeline: record once, investigate repeatedly

Capture a gameplay event once, then import/seek/inspect it through the normal research APIs and fork historical frames back to live execution.

Forensic Timeline v1 stores a deterministic CHQSTATE for every recorded frame and an unfiltered bus-write provenance stream. This intentionally prioritises fidelity and later analysis over storage efficiency.

api timeline.record.start name=turbo-complete-cycle
# run event once
api timeline.record.stop
api timeline.trim.event name=turbo-complete-cycle cpu=A address=0x10040F width=8 mask=02 pre=1 post=1
api timeline.scan.memory name=turbo-complete-cycle

After timeline.load/timeline.seek, the ordinary memory, register, gameplay, sprite and palette inspection APIs operate on the selected historical checkpoint. timeline.fork-live keeps that checkpoint loaded and returns to paused live execution.

Audio limitation

The current native runtime has only sound_stub. Timeline v1 does not claim authentic sound CPU/chip/PCM capture; that capability will be added when native audio emulation exists.

TC0100SCN RAM character inspection

Inspect the 256 RAM-backed 8x8 text characters used by the HUD.

api tile.inspect code=0C palette=0 scale=16

The inspector exports a PNG, pen matrix and JSON metadata from character RAM at 0xC06000 + code*16. Pen 0 is transparent; pens 1..3 use the selected palette bank. v1 does not inspect background ROM tiles.

Physical sprite planes 0,1,2,3 contribute pen bits 3,2,1,0. This is equivalent to reversing the RC2.5 decoded four-bit pen.
