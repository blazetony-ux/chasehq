# RC6.3.1 — Native Reconstruction Phase 2: generated target-health live-function pathway

**Release identity:** `0.67.0.0-RC6.3.1` development source candidate. RC6.3.1 adds opt-in bounded live-function verification (see `docs/RC6.3.1_LIVE_FUNCTION.md`). **Do not claim RC6.3 autonomous function reconstruction completed.** RC6.2.6 has passed the real Windows **bounded instruction-level** M1–M7 technical acceptance (CPU-A 0x820C, 240/240 generated-native commits, CPU state and bus parity, verified forced rollback). That proof remains the baseline and is not invalidated or repeated by this new prototype.

## Actual implemented new functionality

`chqdev native reconstruct --fresh` reads the immutable, verified real Ghidra Run032 ZIP and independently parses the instruction list and lengths of all nine CPU-A windows. It discovers **three distinct contiguous, statically supported candidate ranges**, refusing unknown instructions or branches out of range:

1. CPU-A steering basic block `0x81FC–0x8212` (seven decoded instructions ending RTS). Native C++ is generated from the Ghidra text for MOVEA, MOVE.W, EXT.W, ADDA.W, RTS and its register/ROM/RAM/condition-code behaviour tested against all 193 independently captured signed steering vectors. This is **not** the complete Ghidra steering function `0x81C4–0x8211`.
2. CPU-A sprite-copy block `0x40540–0x40560` (sixteen decoded MOVE.L post-increment transfers), with independently generated C++ RAM/register/flag effects and 112 checked copied longwords across seven different fixtures. Ghidra did not supply a reviewed enclosing function boundary.
3. CPU-A target-health Ghidra function **candidate** `0xA10C–0xA12A` (nine instructions, contiguous across the entire unreviewed Ghidra function range), including TST, BNE/BPL/BRA, SUBQ, MOVE, ADD and RTS. Code generation emits real C++ branching and flags; eight independent controlled state fixtures cover bypass, decrement, underflow/terminal, overflow and update paths. A separately compiled deliberately corrupted branch is **rejected** by the fixtures. Actual live emulation replacement and full coverage are NOT established.

The generated standalone C++17 project is built with local CMake and executed automatically; run output, generated C++, candidate ledger, Ghidra fingerprints, build logs and a SHA-manifest evidence ZIP are emitted. A failed gate still writes an evidence ZIP and returns nonzero. The command's PASS means **supported static candidate generation + offline fixtures passed**, not native promotion.

## Execution

On a developer host with CMake/C++ compiler, from the freshly extracted release:

`./chqdev.bat native reconstruct --fresh` (Windows PowerShell single-line command: `.\chqdev.bat native reconstruct --fresh`)

The existing bounded, ROM-backed acceptance is retained: `.\chqdev.bat native accept --fresh` after the native runtime has been qualified. This remains an instruction-scoped sign-off and does NOT prove RC6.3 functions.

## Explicitly blocked RC6.3 milestones (next engineering phases)

- **M1:** genuine comprehensive headless Ghidra function/decompiler/P-code export for BOTH CPUs, not just fixed historical candidate windows; static function start/end need independent boundary review.
- **M2/M3:** automatic correlated full-function runtime coverage including branch paths, callers, registers, flags, bus and timing; precise live state contracts, cross-CPU/shared-RAM hazards.
- **M4:** extend supported 68000 control/data-flow beyond this strict subset and generate typed, linkable native callable function replacements (standalone C++ compilation alone is not live integration).
- **M5/M6:** original-versus-native full-function live differential on CPU A and B, intervention coverage, safe guarded substitution, forced mismatch and rollback, independent audit; **no RC6.3 function is promoted**.
- **M7:** unattended multi-function ranked/persistent candidate queue, stop/resume, CLI/Workbench/mobile parity and autonomous promotion for independently verified function candidates.

All unsupported candidates remain blocked, never silently replaced with calls back into the original ROM or falsely counted as completed. This is the honest RC6.3 Phase 1 release, **not final autonomous RC6.3 sign-off**. The Windows `qualify --fresh` result is separately pending.
