# Documentation audit - v0.66.9.3-RC3

## Scope

RC3 is the tooling-stabilization candidate on exact final Windows-qualified v0.66.9.2 SHA-256 `f3c730e5bc41886189c11e23d4998967f205b085fa172a9c30fc812330227b26`. It is intended to remain the working build through the next diagnosis phase rather than trigger another immediate rebuild. No intentional gameplay/emulation behavior change is included.

## Evidence incorporated

RC1 exposed Windows evidence-finalization failure. RC2 proved that repair, command-count parity and structured corpus output, then exposed three remaining issues from real Windows evidence: authoritative command lines were still reported as line 1 because the resolved line was not transported to the server; Full Regression growth accounting used top-level compiled items rather than recursive structural commands; and evidence ZIP/index paths were Windows-centric/backslash and the standalone HTML index was not navigable. RC2 also showed a subtler provenance gap: browser/Go client-side `wait` was counted but absent from authoritative command evidence.

## RC3 synchronized contracts

- Current identity is v0.66.9.3-RC3; chqdev v0.5.5.
- Browser and Go execution transport `sourceLine`; nested compiler offsets remain absolute in the resolved source.
- Runs preserve authored `script.chqscript`, `resolved-script.chqscript`, `resolved-commands.txt`, and `resolved-command-map.jsonl`.
- Client-side wait commands are recorded in the authoritative run with `clientRecord=true`.
- Evidence file paths and ZIP entries use `/`; bundle index schema is v2 and the HTML index is clickable/filterable.
- Core run evidence JSON/text is written UTF-8 without BOM where generated by the authoritative finalizer.
- Full Regression growth uses recursive structural counting: v0.66.9.2 baseline 936 structural / 919 executed on Windows; RC3 746 structural.
- RC1 and RC2 focused tooling regressions remain historical; RC3 is current.
- Qualification remains deferred while RC3 is used for diagnosis.
